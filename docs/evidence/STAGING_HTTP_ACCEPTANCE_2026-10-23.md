Before writes, the script checks empty Auth user listing and empty tenants, profiles, memberships, leads, campaigns, lead observations and outbound actions, then checks actual Worker health identity. The actual Worker `conversation-review` owner-read route must deny the client session and return exactly the current tenant owner plus staff for the staff session, excluding the other tenant's owner. An unknown tenant must return 404. No product evidence, contact rights, outbound action or production data is changed.

All fixture cleanup runs in `finally`, scoped only to preselected lead/tenant UUIDs and returned Auth user UUIDs. If an Auth create acknowledgement is lost, a bounded Admin listing recovers only the exact attempted run email. No bulk/unfiltered DELETE exists.
