## Architecture

Existing static HTML/CSS/JavaScript in `site/` retains the Ripe Piper branding. Browser portal/admin use Supabase Auth and PostgREST with RLS. A separate TypeScript Worker in `platform/ripe-piper-platform` serves public forms, booking, proposals, payments, admin actions and dynamic blog pages. It uses a service-role database client, so each Worker route must enforce authorization independently of RLS. Google Workspace handles Calendar/Meet/Gmail/Sheets; payment adapters target Stripe and Razorpay; AI assists meeting notes and proposals; ad APIs supply reporting. Most external credentials are global Worker environment variables, not tenant-specific integrations.

No replacement framework or site is justified. Extend this codebase with shared tenant, lead, campaign, evidence and approval contracts, then small product-specific workflows.

## Database and security findings

20 public tables have RLS enabled. Both dashboard views use `security_invoker=true`. Three migrations are recorded (20261019134626 core, 20261019134629 security/views, 20261019134633 FX). Exact read-only counts: tenants 0, profiles 0, leads 0. Ripe Piper is not onboarded as an operational tenant.

| ID | Severity | Evidence and consequence |
|---|---|---|
| SEC-01 | High | `deals.lead_id` references only lead ID, not `(tenant_id,id)`. Owner INSERT/UPDATE policies validate the deal tenant but not the linked lead tenant. Cross-tenant relationship integrity is not enforced by the schema; reproduce locally before selecting remediation. Similar relationships need review. |
| SEC-02 | High | `postBook` accepts a lead UUID with no expiring booking capability or Turnstile validation and rejects only `not_fit`. A `new`/unsubscribed lead can potentially book; possession of a UUID is the only relationship check. No live exploit attempted. |
| SEC-03 | High | Payment activation is multiple database and email operations, not an atomic transaction/outbox. Concurrent or interrupted webhooks can duplicate or partially apply effects. Sequential mocked replay tests are insufficient. GET proposal approval also initiates payment side effects. |
| SEC-04 | High | Suppression exists but the common email transport does not enforce it. No campaign approval/send ledger, tenant-specific credentials or outbound kill switch exists. Prospect communications remain prohibited. |
| SEC-05 | Medium | Security advisor reports mutable `touch_updated_at` search_path, `btree_gist` in public, and EXECUTE permissions on five security-definer functions for anon/authenticated. `is_*` functions check auth.uid(); two other functions return trigger and cannot simply be treated as callable exploit endpoints. Review grants with dependency tests, not blind revocation. |
| SEC-06 | Medium | Invitations are consumed only by the new-user INSERT trigger. Existing users invited later lack a verified acceptance path; verified-email timing and membership assignment need tests. |
| SEC-07 | High | Initial npm audit: 12 affected packages (2 critical, 6 high, 4 moderate), all in development tooling; this is not proof of an exploited production runtime. See dependency evidence. |
| SEC-08 | Medium | Google Sheets writes use USER_ENTERED for user-supplied fields: formula injection risk. Logs can include provider error payloads. Response headers/CSP, rate limits, retention, recovery and monitoring require validation. |

Security advisor remediation references: [function search path](https://supabase.com/docs/guides/database/database-linter?lint=0011_function_search_path_mutable), [extension schema](https://supabase.com/docs/guides/database/database-linter?lint=0014_extension_in_public), [anonymous definer execution](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [authenticated definer execution](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable).

Performance advisor reports 16 unindexed foreign keys, one auth RLS init-plan warning, 19 overlapping permissive-policy findings, and four unused indexes. These are triage inputs; do not drop protective/unique indexes merely because the empty system has not used them. Log-source aggregation over the default last 24 hours returned pooler/Postgres entries only; no operational journey can be inferred from this.
